# Future roadmap

The continuation already adds local OCR/XLSX, photos/QR/local OTP, dated recurring services/contracts, fleet assignment, resource calendars/truck appointments, whole-pool recovery, admin controls and network intelligence. The remaining work expands or productionizes these working prototypes.

1. **Validated Kerala pilot:** verify hydrographic/clearance/depth, vessel/terminal capabilities, certificates, dangerous-goods processes, real demand/capacity and rates with operators and authorized sources. Replace synthetic records with dated provenance and freshness rules.
2. **Provider evaluation:** configure real LLM and Malayalam STT; evaluate varied recorded speech and labeled PO/invoice/BOQ documents, including Malayalam OCR. Measure errors and missing fields on real data. Deploy isolated, resource-limited recognition workers and multilingual reviewed extraction; keep disclosed fallback.
3. **Commercial workspace gaps:** preferred-operator management, operator quote negotiation/rate heatmaps, contract-specific invoicing/penalties, dedicated 3PL SLA/cost/scorecard views and automated lateness notifications. Pilot possible transaction fee, operator subscription and enterprise SaaS; these are business hypotheses.
4. **Execution expansion:** live GPS on the actual shipment map, authoritative tide/lock/weather/notice feeds, full truck gate lifecycle, labor/crew qualification and long-term storage inventory, private object storage/retention and production SMS/email delivery challenges. Keep prototype receipt names separate from legal signatures.
5. **Optimization expansion:** multi-tour fleet VRP, validated relocation dispatch, split loads, broader return-corridor overlap, mid-voyage transshipment/rescue and real demand-confirmed recurring services. Train ETA/risk only after sufficient real voyage evidence; current rule scores remain transparent.
6. **Production identity/data:** managed OIDC/OAuth2/SSO, enrollment and tenant policies, audit retention, versioned PostgreSQL migration, resource/service/contract concurrency locks, backups/restore and contention/load tests. Preserve the SQLite demo while rehearsing a separate deployment.
7. **Real integrations:** authorized WhatsApp Business, actual payment/escrow/refund, insurance policies and government document submissions through the existing contracts. No-op providers never fabricate success. Predictive maintenance and cold-chain IoT remain lower-priority P3 extensions.
8. **Publication/deployment:** after explicit user approval, push the configured origin using the prepared commands (or create a different repository if requested), verify its visibility/content, update the submission URL, and rehearse hosting with appropriate identity/data controls. The supplied nine-slide outline can be turned into a presentation separately.

Government reliability/rate/modal-shift/activation outputs need real sample histories and audited assumptions before policy use. Flood/emergency operations require verified observations, authorization and procedures; the current deterministic scenario is not an emergency dispatch service.
