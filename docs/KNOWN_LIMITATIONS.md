# Known limitations

The original P0/P1 vertical slice and high-value continuation workflows execute real application logic. The complete requirement-by-requirement assessment is [Feature audit](FEATURE_AUDIT.md); working prototypes are distinguished from partial workflows and production requirements.

- Operational depths, dimensions, rates, resources, certificates, reliability history and emissions factors are synthetic. PASS means only passed configured demo constraints. The four-node/three-segment graph is approximate; it does not establish legal navigation, surveyed geometry, tide-dependent depth or real lock bookings.
- Road distance uses haversine × 1.35 and disclosed speeds/handling assumptions. No trained ETA/reliability model or certified emissions factor is claimed.
- Local text/voice extraction is deterministic and narrow. External LLM/STT adapters, schema checks, diagnostics and mocked failure tests work, but real credentials were unavailable. Native/transliterated/mixed Malayalam variants are tested; broad multilingual accuracy is not measured.
- Actual local ONNX OCR handles scanned PDFs/images. Text PDF extraction runs first; OCR reads at most four pages and labels truncation. English synthetic samples are verified; Malayalam OCR and a real invoice/BOQ corpus are not validated. Generic fields are extracted for review, not legal/accounting interpretation. Worker timeouts and byte/pixel/page limits are useful bounds, not a complete hostile-document sandbox.
- XLSX import supports one active sheet, at most 200 rows/40 columns and 32 MB decompressed content. It rejects formulas, macros/external links and duplicate mapped headers. It does not evaluate formulas or infer missing timezone offsets.
- Fleet optimization assigns at most one common-corridor voyage per vessel, up to 40 cargo/12 vessels. It prioritizes served tonnage before the chosen secondary objective. It is not a full multi-tour VRP or split-load solver. Pooling is common-terminal and needs confirmed volumes.
- Recurring patterns generate concrete dated services over at most 90 days, with up to 12 reservations per approval. Physical vessel overlap is rechecked at booking; generated calendar instances are proposals, not guaranteed vessel availability. Capacity contracts hold and draw per-departure tonnes and apply agreed freight rates, but do not issue legal contracts, penalties or recurring invoices.
- Terminal scheduling uses configurable resources and peak overlapping capacity, fixed 0.75-hour handling windows and bounded alternate-slot search. Storage reservations cover handling windows, not long-term warehouse inventory. Truck gate appointments can be reserved; full gate lifecycle/scanner integration is partial. Crew assignment is a coordination record, not labor qualification/rostering.
- Recovery handles eight pre-departure disruption types and can approve an entire pool atomically. Later departure, scheduled service, vessel/terminal and road alternatives are revalidated. Mid-voyage rescue/transshipment, splitting a load and production exception feeds remain roadmap.
- Positions on the shipment map are simulated. Optional GPS/weather read adapters validate schema, freshness and location with disclosed fallback; they are not connected AIS/IMD feeds and do not override hard safety. Captain cached views are read-only; disconnected write synchronization is not implemented.
- Photos are private canonical JPEGs stored in prototype database records, not scalable object storage with retention controls. QR labels contain opaque references and require authorization. Generic phone cameras may need an application base URL configured in a future deployment; the current label payload is a relative in-app reference.
- Prototype OTP is local/demo only, expiring, salted/hashed and single-use. Requesting a challenge enforces receiver verification before delivery. Preserved milestone-only demo deliveries remain **unverified**. Names/photos/quantities are acceptance evidence, not legal digital signatures; SMS/email delivery remains unconnected.
- Corridor statistics use actual app milestones, deduplicate common voyages and withhold scores below five completed voyages. Rate ranges require at least three comparable observations; five seeded hero-corridor observations are explicitly synthetic cost-model history, not market rates. Modal-shift replay uses current demo availability and original time slack, not historical safety reconstruction or guaranteed future conversion.
- Crowd reports are user observations. Platform VERIFIED/DISPUTED review is not official authority verification. Only explicit promotion creates a temporary conservative restriction. Voice reporting, automated corroboration and official notice ingestion remain extensions.
- Fifteen role workspaces have working core tasks. Preferred-operator management, commercial quote negotiation, dedicated operator rate/heatmap views, full fleet maps, automatic SLA monitoring and some detailed scorecards are partial. See the feature audit rather than treating a stored architecture field as a completed workflow.
- Payment/dispute/settlement states move no funds. Insurance/government defaults return Not connected; generated packages are prototype JSON data, not official invoices, manifests, e-way bills or authorized submissions.
- Admin creates organizations/users, changes stored roles and disables users. Demo switching is intentionally not production authentication. Signed identity is preserved; managed OIDC/OAuth2/SSO, onboarding and policy provisioning are production requirements.
- SQLite is the verified demo database. PostgreSQL needs a pinned driver, reviewed versioned migrations, resource/service row-lock design and real concurrency/restore tests. The migration guide is readiness work, not a completed PostgreSQL deployment.
- An existing GitHub origin is configured for `Dony-sunny/keralAI_hack`. This continuation performed no push; remote visibility/content was not verified. Exact commands and metadata are provided for an approved push, and no hosted deployment was performed. The requested nine-slide outline exists; no actual presentation deck was requested or published. WhatsApp, predictive maintenance, cold-chain IoT and real commerce/government connectors remain roadmap.
