## Style Guidelines

**Style:** Minimalism & Swiss Style

**Keywords:** Clean, simple, spacious, functional, white space, high contrast, geometric, sans-serif, grid-based, essential

**Best For:** Enterprise apps, dashboards, documentation sites, SaaS platforms, professional tools

**Key Effects:** Subtle hover (200-250ms), smooth transitions, sharp shadows if any, clear type hierarchy, fast loading

### Page Pattern

**Pattern Name:** Real-Time / Operations Landing

- **Conversion Strategy:** Offer a demo or sandbox and show trust signals. Label telemetry as live only when backed by a current source, with update time and stale state. Provide pause/hide or update-frequency controls for tickers and previews, stop offscreen/hidden work, support keyboard controls, and render a static final snapshot under reduced motion.
- **CTA Placement:** Primary CTA in nav + After metrics
- **Section Order:** Hero (product + live preview or status) > Key metrics/indicators > How it works > CTA (Start trial / Contact)

## Anti-Patterns (Do NOT Use)

- ❌ Static tracking
- ❌ No map integration
- ❌ AI purple/pink gradients

### Additional Forbidden Patterns

- ❌ **Emojis as icons** — Use SVG icons (Heroicons, Lucide, Simple Icons)
- ❌ **Missing cursor:pointer** — All clickable elements must have cursor:pointer
- ❌ **Layout-shifting hovers** — Avoid scale transforms that shift layout
- ❌ **Low contrast text** — Maintain 4.5:1 minimum contrast ratio
- ❌ **Instant state changes** — Always use transitions (150-300ms)
- ❌ **Invisible focus states** — Focus states must be visible for a11y

## Pre-Delivery Checklist

Before delivering any UI code, verify:

- [ ] No emojis used as icons (use SVG instead)
- [ ] All icons from consistent icon set (Heroicons/Lucide)
- [ ] `cursor-pointer` on all clickable elements
- [ ] Hover states with smooth transitions (150-300ms)
- [ ] Light mode: text contrast 4.5:1 minimum
- [ ] Focus states visible for keyboard navigation
- [ ] `prefers-reduced-motion` respected
- [ ] Responsive: 375px, 768px, 1024px, 1440px
- [ ] No content hidden behind fixed navbars
- [ ] No horizontal scroll on mobile

## Applied project decisions

This is an existing React logistics application, not a marketing landing page.
Use the skill's minimal, readable layout guidance with the established green
identity: primary #17634d, text #203c32, muted text #52675f, background #f6f8f6.
Use the existing system sans-serif font stack to avoid remote font dependencies.
The main cargo workflow has four steps with a plain-language next action, one

## Marketplace redesign (current)

The current interface follows the user's requested familiar shopping marketplace
pattern: horizontal search header, boat catalogue, route/capacity filters, cargo
posting, operator listings, and booking checkout. The main application no longer
uses a dashboard sidebar. Use navy #102730 and #16313d for navigation, teal #176f71
for identity and matching, and amber #f4bd57 for primary marketplace actions.
Boat illustrations represent listing categories; do not imply actual vessel photos.
Show base boat rates separately from the complete delivery quote. Do not invent
ratings, availability, savings or certified environmental claims.

## Boat operator marketplace

Use the same navy header, amber actions, illustrated boat cards and readable
forms as the cargo owner marketplace. Separate Cargo requests, Find cargo,
My boats, List your boat and My departures. Summarize load, route, dates,
approved delivery revenue and estimated contribution in each request. Put
resource and cost assumptions behind expandable details. Listing forms review
route/capacity/volume/dates before saving; edits preserve the listing identifier.
Unbooked listings can be paused and republished. Reserved windows remain locked.

## Logistics marketplace

Use delivery cards with a single next action, approval status, cargo summaries,
provider assignments, a progress timeline, and individual receipt forms. Keep
booking references and recovery controls behind expandable details. The demo
loader adds labelled synthetic boats, cargo and delivery examples without resetting
existing work. Cargo-owner browsing shows matching windows rather than unsuitable
labels and disabled boat cards. Backend feasibility checks remain authoritative.

## Working forms and role handoffs

Register a new vessel and its first availability together. Keep physical
measurements visible and require review; local demo certificate review is an
explicit choice and must never imply real certificate verification. Suggest
piece count from cargo weight while allowing users to review actual dimensions.
An estimated negative contribution requires the owning operator's explicit
acknowledgment, rather than preventing every small shipment from being booked.
Preserve safety checks, cargo ownership, exact quote versions and all provider
approvals. Handoffs select the boat's actual operator account and clear unrelated
search filters. Keep one handoff action per departure and offer replanning for
expired or declined quotes. Verify new manual entries through a persisted receipt.
